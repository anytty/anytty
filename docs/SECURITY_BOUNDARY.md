# AnyTTY Security Boundary

This document describes AnyTTY's user-visible security promises: authority, encrypted transport, pairing, revocation, and local data handling.

## Terminal authority

- The daemon running on the user's machine is the final authority for terminals, files, history, device identity, and client access.
- A client receives only the capabilities explicitly granted by that daemon. Access can be reviewed and revoked from the daemon.
- A connection route, including AnyTTY Cloud, can help a client reach a daemon but cannot grant terminal or file permissions or expand an existing grant.

## Transport and relay

- Remote connections authenticate the daemon identity and protect terminal and file traffic with encryption in transit.
- P2P and Relay are transport choices. A Relay forwards encrypted traffic and does not become the authority for terminal or file operations.
- Authentication, identity, or authorization failures are rejected. Route fallback must not silently weaken a security decision.

## Pairing and revocation

- Pairing is initiated by the user with a short-lived claim generated by the target daemon.
- A successful pairing grant is bound to the client's identity; copying endpoint metadata alone does not copy access.
- An unredeemed pairing QR or claim must be treated as a secret. Lost or untrusted clients should be revoked from the daemon.

## Local data and logging

- Terminal history is stored on the daemon machine. Clients store only the endpoint and credential material needed for their authorized access.
- Credentials use platform-protected storage where the platform provides it.
- Logs, issue reports, screenshots, and test fixtures must not contain private keys, pairing claims, access grants, terminal content, file content, or personal data.
- The managed service may process the connection metadata required to establish a route, but terminal and file permissions remain under daemon control.

Report suspected vulnerabilities through [GitHub private vulnerability reporting](https://github.com/anytty/anytty/security/advisories/new). Do not disclose credentials or user data in a public issue.
