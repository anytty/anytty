# AnyTTY 安全边界

本文说明 AnyTTY 对用户提供的安全承诺，包括权限归属、加密传输、配对、撤销和本地数据处理。

## 终端权限

- 运行在用户机器上的 daemon 是终端、文件、历史记录、设备身份和客户端访问权限的最终权威。
- 客户端只能获得 daemon 明确授予的能力；用户可以在 daemon 上查看并撤销这些访问权限。
- 包括 AnyTTY Cloud 在内的连接方式只能帮助客户端到达 daemon，不能授予终端或文件权限，也不能扩大已有授权。

## 传输与 Relay

- 远程连接会验证 daemon 身份，并对传输中的终端与文件数据进行加密保护。
- P2P 与 Relay 只是不同的传输路径。Relay 负责转发加密流量，不会成为终端或文件操作的权限主体。
- 身份、认证或授权失败时会直接拒绝连接；切换连接路径不能静默降低安全要求。

## 配对与撤销

- 配对由用户主动发起，并使用目标 daemon 生成的短期 claim。
- 配对成功后的授权与客户端身份绑定；仅复制 endpoint 信息不能复制访问权限。
- 尚未兑换的配对二维码或 claim 应视为秘密。客户端丢失或不再可信时，应从 daemon 撤销其访问权限。

## 本地数据与日志

- 终端历史记录保存在 daemon 所在机器上；客户端只保存已授权访问所需的 endpoint 与凭据材料。
- 平台提供安全存储能力时，凭据会保存在受平台保护的存储中。
- 日志、Issue、截图和测试数据不得包含私钥、配对 claim、访问授权、终端内容、文件内容或个人数据。
- 托管服务可能处理建立连接所需的连接元数据，但终端与文件权限始终由 daemon 控制。

如发现安全问题，请使用 [GitHub 私密漏洞报告](https://github.com/anytty/anytty/security/advisories/new)，不要在公开 Issue 中披露凭据或用户数据。
