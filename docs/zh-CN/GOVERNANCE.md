# 治理

AnyTTY 当前采用适合预发布项目的维护者主导模式。

贡献者通过 issue 和 pull request 提议变更。维护者负责技术方向、安全边界、发布、仓库权限和社区治理；当前维护团队以 `CODEOWNERS` 为准。

常规决定在 pull request review 中完成。涉及公开协议、信任边界、兼容性、依赖或治理的重要变化应先创建公开 issue，并在代码或稳定文档中记录结论。维护者优先寻求共识；无法形成共识时，由负责的 code owner 决定并记录理由。

合并至少需要一名维护者批准。认证、授权、配对、公开协议、发布自动化和本治理政策的变化需要仓库所有者明确审查，贡献者不能批准自己的变更。

维护者按 `RELEASE_CHECKLIST.md` 决定提交是否可发布。安全问题遵循 `SECURITY.md`，协调披露前保持 embargo。未来扩大维护团队时，会另行记录提名流程；持续高质量贡献和可靠的用户安全判断是获得更高权限的前提。
