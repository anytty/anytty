# Connection routes

An endpoint identifies a daemon. Routes are different ways to reach it, and policy controls which route is used and when to fall back.

## Local

Uses the current user's local socket. Filesystem permissions and the daemon identity anchor trust. No Cloud is required.

## SSH

Uses OpenSSH, then reaches loopback signaling and ICE-TCP on the remote machine. Pin and verify the SSH host key. No Cloud is required.

## Direct

Connects to published signaling and ICE-TCP addresses, bound to the paired daemon identity and route credential. No Cloud is required.

## Cloud

Uses managed device discovery and connection negotiation, preferring P2P and using Relay fallback when a direct path is unavailable.

## Inspect endpoints

```sh
./.artifacts/bin/anytty endpoint list
./.artifacts/bin/anytty endpoint show <endpoint-id>
./.artifacts/bin/anytty endpoint test <endpoint-id>
```

Use command help from the exact checkout before adding or changing a route: `anytty endpoint --help`. If a route is not authorized, AnyTTY fails closed instead of silently falling back to a weaker connection.
