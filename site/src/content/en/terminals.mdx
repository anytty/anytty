# Terminal management

A terminal remains owned by the daemon while clients attach, detach, reconnect, or switch between live output and retained history.

## Core lifecycle

```sh
anytty terminal create --attach -- zsh
anytty terminal list
anytty terminal attach <terminal-id>
anytty terminal show <terminal-id>
anytty terminal kill <terminal-id>
anytty terminal remove <terminal-id>
```

Run `anytty terminal --help` for the exact flags in the current checkout. Killing stops the process; removing deletes an exited terminal record.

## Live and history

Live rendering and history consumption use separate cursors. A client may freeze its history viewport while new output continues, then return to the current live frame without making the terminal process dependent on that client.

> **Bounded by design.** Per-terminal output and subscriber queues have byte budgets. Overflow behavior is explicit; slow or disconnected clients do not create unbounded daemon memory growth.
