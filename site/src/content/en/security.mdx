# Security model

AnyTTY keeps terminal and file permissions on the daemon. A connection route can decide whether you can reach a machine, but it cannot grant more access than the daemon already issued.

## Security invariants

- Pairing claims are short-lived, one-time, and cannot be replayed.
- Access grants are tied to a specific client and enforced by the daemon.
- Remote connections authenticate the daemon identity and encrypt terminal and file traffic.
- A Relay forwards encrypted traffic without gaining terminal or file permissions.
- If authentication or authorization fails, the connection is rejected instead of falling back to weaker checks.

## Report a vulnerability

Do not open a public issue. Use [GitHub private vulnerability reporting](https://github.com/anytty/anytty/security/advisories/new) with a minimal reproduction based on generated test credentials. Never include real keys, pairing claims, grants, terminal content, or personal data.

Read the full [security policy](https://github.com/anytty/anytty/blob/main/SECURITY.md) and [security boundary](https://github.com/anytty/anytty/blob/main/docs/SECURITY_BOUNDARY.md).
