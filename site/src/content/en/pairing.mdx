# QR pairing

AnyTTY mobile apps add endpoints only when a user scans a QR code generated by the target service. They do not log in, import arbitrary text claims, or discover devices from a Cloud account.

## Trust sequence

1. **The daemon creates a short-lived claim.** The offer is bound to the daemon identity, requested capabilities, and a single enrollment flow.
2. **The client scans and proves its identity.** The native client stores endpoint data and credentials in platform-protected storage.
3. **The daemon issues client-bound access.** Consumption is recorded so the same claim cannot be replayed.

> **Treat an unredeemed QR as a secret.** Do not place pairing URIs in logs, screenshots, issue reports, chat, or version control. Revoke a grant from the daemon if a client is lost or no longer trusted.

Protocol details and failure rules are in the repository's [pairing specification](https://github.com/lozzo/anytty/blob/main/docs/PAIRING_PROTOCOL.md).
